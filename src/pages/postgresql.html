PostgreSQL

banco de dados avançado

sqldatabasepostgres41 comandos

Resumo

PostgreSQL é um banco relacional open source focado em correção e recursos avançados: transações ACID, JSONB, window functions, CTEs e extensões como PostGIS.

  • Para que serve: guardar dados estruturados com integridade, consultá-los com SQL rico e escalar leitura com índices e réplicas.
  • Quando usar: a maioria das aplicações backend que precisam de consistência, consultas analíticas moderadas, dados semiestruturados em JSONB ou geográficos.
  • Quando evitar: cache de altíssima frequência (use Redis), séries temporais ou eventos em volume massivo sem extensões específicas, e armazenamento de arquivos grandes.

Dica

Os comandos de estrutura (DDL: CREATE, ALTER, DROP) também rodam dentro de transações no PostgreSQL, então dá para testar uma migração e desfazer com ROLLBACK.

Conceitos-chave

Banco, schema e tabela

Um servidor tem vários bancos; cada banco tem schemas (o padrão é public), que agrupam tabelas, views e funções.

Índice

Estrutura que acelera buscas. B-tree atende igualdade e intervalos; GIN atende JSONB, arrays e busca textual.

Transação e MVCC

Cada transação enxerga um snapshot consistente; escritas criam novas versões das linhas, então leitores não bloqueiam escritores.

EXPLAIN ANALYZE

Mostra o plano que o planner escolheu e o tempo real de cada etapa. É o ponto de partida para otimizar uma query.

Window function

Calcula sobre um conjunto de linhas relacionadas sem agrupá-las, como ranking com ROW_NUMBER() OVER (PARTITION BY …).

VACUUM

Recupera o espaço das versões antigas de linhas deixadas pelo MVCC e atualiza estatísticas. O autovacuum faz isso automaticamente.

pg_dump e backup

pg_dump exporta um banco de forma consistente; pg_restore ou psql restauram o backup.

🔍 Consultas Avançadas

JOIN com agregaçãoSELECT u.name, COUNT(p.id) as posts
FROM users u
LEFT JOIN posts p ON u.id = p.user_id
GROUP BY u.id, u.name
HAVING COUNT(p.id) > 0;
Window functionsSELECT name, salary,
  RANK() OVER (ORDER BY salary DESC) as rank
FROM employees;
Common Table ExpressionWITH monthly_sales AS (
  SELECT DATE_TRUNC('month', created_at) as month,
    SUM(amount) as total
  FROM orders GROUP BY 1
)
SELECT * FROM monthly_sales;
Full-text searchSELECT * FROM articles
WHERE to_tsvector('english', content) @@
  to_tsquery('english', 'database & query');
JSON operationsSELECT data->>'name' as name,
  data->'address'->>'city' as city
FROM users WHERE data @> '{"active": true}';
Array operationsSELECT * FROM posts
WHERE tags && ARRAY['python', 'flask'];

⚡ Performance & Otimização

EXPLAIN ANALYZEEXPLAIN ANALYZE SELECT * FROM users WHERE email = 'test@example.com';
Ver índicesSELECT * FROM pg_indexes WHERE tablename = 'users';
Vacuum analyzeVACUUM ANALYZE users;
Ver locksSELECT * FROM pg_locks WHERE NOT granted;
Ver conexões ativasSELECT * FROM pg_stat_activity;
Cache hit ratioSELECT sum(blks_hit)*100/sum(blks_hit+blks_read) as cache_hit_ratio FROM pg_stat_database;
Tamanho das tabelasSELECT schemaname, tablename,
  pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename))
FROM pg_tables ORDER BY pg_total_relation_size(schemaname||'.'||tablename) DESC;

Armadilhas & Fixes

ErroCausaCorreção
could not connect to server / no pg_hba.conf entryO servidor não escuta no endereço usado (listen_addresses) ou o pg_hba.conf não libera aquele usuário, banco e IP.Ajuste listen_addresses no postgresql.conf, adicione a regra no pg_hba.conf e recarregue com SELECT pg_reload_conf();.
ERROR: deadlock detectedDuas transações bloquearam linhas em ordem inversa e cada uma espera a outra; o PostgreSQL aborta uma delas.Acesse as linhas sempre na mesma ordem, mantenha transações curtas e trate o erro tentando de novo.
Query lenta com Seq ScanFalta índice na coluna do WHERE ou JOIN, ou as estatísticas estão desatualizadas.Rode EXPLAIN ANALYZE, crie o índice com CREATE INDEX CONCURRENTLY e atualize as estatísticas com ANALYZE tabela;.
