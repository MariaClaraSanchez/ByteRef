Flask

microframework web Python

pythonwebapi30 comandos

Resumo

Flask é um microframework web em Python: entrega roteamento, requisição/resposta e templates, e deixa o resto (banco de dados, autenticação, validação) para extensões que você escolhe.

  • Para que serve: criar APIs e aplicações web pequenas e médias com pouco código e controle total sobre as dependências.
  • Quando usar: APIs REST, microsserviços, protótipos e painéis internos; projetos em que você quer escolher cada peça.
  • Quando evitar: quando você quer tudo pronto (admin, ORM, autenticação) como no Django, ou quando a API é fortemente assíncrona e tipada, cenário em que o FastAPI se encaixa melhor. Para deploy, use um servidor WSGI como Gunicorn, nunca o servidor de desenvolvimento.

Conceitos-chave

App e factory

O objeto Flask(__name__) é a aplicação. A função factory create_app() cria e configura a app, facilitando testes e múltiplos ambientes.

Rota e view

@app.route('/users/<int:id>') liga uma URL e métodos HTTP a uma função (view) que devolve a resposta.

Blueprint

Agrupa rotas, templates e arquivos estáticos de uma parte da aplicação, registrados na app com um prefixo de URL.

Request e Response

request traz dados da requisição (args, JSON, form, headers); a view devolve texto, JSON, template ou um objeto Response.

Contexto de aplicação

current_app, g e request só existem durante uma requisição ou dentro de app.app_context().

Extensões

Pacotes como Flask-SQLAlchemy (banco), Flask-Login (autenticação) e Flask-Migrate somam recursos sem acoplar o núcleo.

Armadilhas & Fixes

ErroCausaCorreção
RuntimeError: Working outside of application contextCódigo usa current_app, db ou g fora de uma requisição, por exemplo num script ou no shell.Envolva o código em with app.app_context(): ou use flask shell, que já cria o contexto.
404 em rota que existeA barra final não bate: /users e /users/ são rotas diferentes, ou o blueprint foi registrado com outro url_prefix.Liste as rotas com flask routes e padronize a barra final na definição.
Debugger exposto em produçãoA app rodou com debug=True ou flask run --debug num servidor público; o debugger permite executar código remotamente.Em produção, rode com gunicorn 'app:create_app()' e sem modo debug.

Debug em produção é execução remota de código

O debugger interativo do Werkzeug executa Python enviado pelo navegador. Nunca ative o modo debug fora da sua máquina.
