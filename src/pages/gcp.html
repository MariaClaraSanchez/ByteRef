GCP

Google Cloud Platform

gcloudgsutilCloud Run26 comandos

Resumo

Google Cloud Platform é a nuvem do Google. Tudo vive dentro de um projeto, com acesso controlado pelo IAM e operado pelo gcloud (após gcloud auth login) ou pelo console.

  • Para que serve: rodar containers sem servidor (Cloud Run), máquinas virtuais (Compute Engine), guardar arquivos (Cloud Storage) e imagens (Artifact Registry).
  • Quando usar: deploy de APIs e jobs em containers com escala automática, ambientes que já usam Google Workspace ou BigQuery, e projetos que precisam de infraestrutura gerenciada.
  • Quando evitar: quando a empresa já padronizou outra nuvem, ou para cargas pequenas e estáveis em que uma VPS simples custa menos e dá menos trabalho.

Conceitos-chave

Projeto

Unidade de organização e cobrança. Recursos, APIs ativadas, permissões e cotas pertencem a um projeto (--project).

IAM

Controla quem pode fazer o quê. Papéis (roles) são concedidos a usuários ou a contas de serviço, usadas por aplicações.

Cloud Run

Roda containers sem gerenciar servidores: escala conforme as requisições, inclusive para zero, e cobra pelo uso.

Compute Engine

Máquinas virtuais com controle total do sistema operacional, para cargas que não cabem em containers sem servidor.

Cloud Storage

Armazenamento de objetos em buckets (gs://) para arquivos, backups e conteúdo estático.

Artifact Registry

Registry de imagens e pacotes do GCP. Substitui o antigo Container Registry (gcr.io).

Configuração do gcloud

Conjunto nomeado de conta, projeto e região padrão. Permite alternar entre ambientes sem repetir flags.

🚀 Cloud Run

Deploy de serviçogcloud run deploy SERVICO --image gcr.io/PROJ/IMG --platform managed --region us-central1 --allow-unauthenticated
Deploy com env varsgcloud run deploy SERVICO --image IMG --set-env-vars DB_URL=postgres://...
Listar serviçosgcloud run services list --platform managed
Descrever serviçogcloud run services describe SERVICO --region us-central1
Deletar serviçogcloud run services delete SERVICO --region us-central1
Mínimo de instâncias (evitar cold start)gcloud run services update SERVICO --min-instances=1
Ver URL do serviçogcloud run services describe SERVICO --format='value(status.url)'

Armadilhas & Fixes

ErroCausaCorreção
PERMISSION_DENIEDA conta ativa (usuário ou conta de serviço) não tem o papel IAM necessário no projeto ou no recurso.Verifique roles IAM: gcloud projects get-iam-policy PROJETO — adicione o role necessário ao Service Account.
Cloud Run: Container failed to startO container não escuta na porta da variável PORT (padrão 8080) ou falha ao iniciar.O Cloud Run espera PORT=8080. Certifique-se que a app escuta em 0.0.0.0:8080 e o Dockerfile expõe essa porta.
Quota exceededO projeto atingiu a cota daquele recurso na região escolhida.IAM & Admin → Quotas no console. Mude de região ou solicite aumento. Use gcloud compute regions list para ver alternativas.
gcloud: command not foundO Google Cloud CLI não está instalado ou não está no PATH.Instale o SDK: curl https://sdk.cloud.google.com | bash e reinicie o shell.
Cloud Run: too many requests (429)Todas as instâncias atingiram o limite de concorrência e o número máximo de instâncias foi alcançado.Aumente --concurrency e --max-instances no deploy. Ou use Cloud Tasks para processar filas.

Remoção definitiva

gcloud run services delete apaga o serviço e todas as revisões; a URL deixa de responder na hora. Confira o projeto ativo com gcloud config list antes.
