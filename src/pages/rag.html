RAG & Embeddings

busca semântica e respostas com contexto

ragembeddingspgvector10 comandos

Resumo

RAG (retrieval-augmented generation) responde perguntas buscando trechos relevantes nos seus documentos e enviando esses trechos ao LLM junto com a pergunta. A busca usa embeddings: vetores em que textos de significado parecido ficam próximos.

  • Para que serve: fazer o modelo responder com base em dados privados ou atualizados (manuais, base de conhecimento, tickets) e citar a fonte.
  • Quando usar: a resposta está em documentos seus, que mudam com frequência ou são grandes demais para caber inteiros no contexto (veja janela de contexto).
  • Quando evitar: quando poucos documentos cabem inteiros no prompt (mais simples e preciso), ou quando a pergunta exige agregações exatas, que são melhor resolvidas com SQL.

Embeddings com a API do Claude

A Anthropic não oferece modelo de embeddings próprio; a documentação oficial indica o Voyage AI. Os exemplos usam voyage-4 (1024 dimensões) e pgvector no PostgreSQL. Referência: out/2026.

Conceitos-chave

Embedding

Vetor de números que representa o significado de um texto. Textos parecidos geram vetores próximos, mesmo sem palavras em comum.

Similaridade

Medida de proximidade entre vetores, geralmente cosseno. Com vetores normalizados, como os do Voyage AI, produto escalar e cosseno dão o mesmo ranking.

Chunking

Divisão dos documentos em trechos menores antes de gerar embeddings, para que cada vetor represente um assunto e caiba no contexto.

Banco vetorial

Armazena os embeddings e busca os mais próximos de um vetor de consulta, como o pgvector no PostgreSQL com índice HNSW.

Retrieval (top-k)

Etapa que recupera os k trechos mais similares à pergunta para montar o contexto enviado ao LLM.

Reranking

Segunda etapa opcional: um modelo reordena os candidatos da busca por relevância real, melhorando a precisão do top-k.

⚙️ Setup & SQL

Instalar dependênciaspip install -U voyageai anthropic "psycopg[binary]" pgvector numpy
Definir a chave do Voyage AIexport VOYAGE_API_KEY="sua-chave"
Habilitar o pgvector no bancoCREATE EXTENSION IF NOT EXISTS vector;
Tabela de chunks (1024 dimensões)CREATE TABLE chunks (id bigserial PRIMARY KEY, fonte text, conteudo text, embedding vector(1024));
Índice HNSW por distância de cossenoCREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops);
5 trechos mais próximos (<=> = cosseno)SELECT fonte, conteudo FROM chunks ORDER BY embedding <=> '[0.01, -0.02, ...]' LIMIT 5;

🗂️ Indexação

Python · chunking com sobreposição
def chunk(texto: str, tamanho: int = 1200, sobreposicao: int = 200) -> list[str]:
    """Divide em pedaços de ~tamanho caracteres, repetindo o fim do anterior."""
    passo = tamanho - sobreposicao
    return [texto[i:i + tamanho] for i in range(0, len(texto), passo)]
Python · gerar embeddings e gravar no pgvector
import numpy as np
import psycopg
import voyageai
from pgvector.psycopg import register_vector

vo = voyageai.Client()  # lê VOYAGE_API_KEY do ambiente
pedacos = chunk(open("manual.md").read())
vetores = vo.embed(pedacos, model="voyage-4", input_type="document").embeddings

with psycopg.connect("postgresql://localhost/app") as conn:
    register_vector(conn)
    with conn.cursor() as cur:
        for texto, vetor in zip(pedacos, vetores):
            cur.execute(
                "INSERT INTO chunks (fonte, conteudo, embedding) VALUES (%s, %s, %s)",
                ("manual.md", texto, np.array(vetor)),
            )

🔎 Consulta & resposta

Python · buscar os trechos mais próximos
pergunta = "Como redefino a senha?"
q = np.array(vo.embed([pergunta], model="voyage-4", input_type="query").embeddings[0])

with psycopg.connect("postgresql://localhost/app") as conn:
    register_vector(conn)
    trechos = conn.execute(
        "SELECT fonte, conteudo FROM chunks ORDER BY embedding <=> %s LIMIT 5",
        (q,),
    ).fetchall()
Python · responder com o contexto recuperado
import anthropic

contexto = "\n\n".join(
    f'<documento fonte="{fonte}">\n{conteudo}\n</documento>' for fonte, conteudo in trechos
)

client = anthropic.Anthropic()
response = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=16000,
    system=(
        "Responda só com base nos documentos fornecidos e cite a fonte. "
        "Se a resposta não estiver nos documentos, diga que não sabe."
    ),
    messages=[{"role": "user", "content": f"{contexto}\n\nPergunta: {pergunta}"}],
)
print(next(b.text for b in response.content if b.type == "text"))

Armadilhas & Fixes

ErroCausaCorreção
Busca traz trechos irrelevantes ou incompletosChunks grandes demais misturam vários assuntos num vetor; pequenos demais perdem o contexto da frase.Divida por seção ou parágrafo, use sobreposição, teste tamanhos com perguntas reais e considere um reranker.
Similaridade sem sentido depois de trocar o modeloDocumentos e perguntas foram vetorizados com modelos ou dimensões diferentes, que não são comparáveis.Use o mesmo modelo e a mesma dimensão nas duas fases; ao trocar de modelo, reindexe tudo e guarde o nome do modelo junto do vetor.
Ranking pior que o esperadoO input_type foi usado ao contrário ou omitido: documentos e perguntas são otimizados de formas diferentes.Use input_type="document" na indexação e input_type="query" na pergunta.
LLM ignora os documentos ou inventaO prompt não obriga o uso do contexto, ou os trechos recuperados não contêm a resposta.Instrua a responder só com base nos documentos, citar a fonte e dizer que não sabe; registre em log os trechos recuperados para depurar.

Prompt injection nos documentos

Trechos recuperados são dados, não instruções: um documento pode conter "ignore as regras anteriores". Delimite o contexto (ex.: tags <documento>), deixe as regras no system prompt e não dê ao modelo ações perigosas com base nesse conteúdo.
