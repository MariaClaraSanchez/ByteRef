Redis

cache, filas e pub/sub

redis-clicachepub/sub23 comandos

Resumo

Redis é um banco em memória de chave e valor, com estruturas de dados nativas (string, hash, list, set, sorted set) e mensagens pub/sub.

  • Para que serve: cache de baixa latência, sessões, filas simples, rate limiting, rankings e contadores.
  • Quando usar: dados acessados com muita frequência que podem ser recalculados ou têm validade (TTL), e coordenação rápida entre serviços.
  • Quando evitar: como única fonte de dados críticos sem persistência configurada, para dados maiores que a memória disponível ou para consultas relacionais complexas.

Conceitos-chave

Chave e TTL

Todo valor vive numa chave (ex.: sessao:abc123). O TTL define quando a chave expira e é removida automaticamente.

Tipos de dados

String, Hash (objeto com campos), List (fila), Set (conjunto sem repetição) e Sorted Set (conjunto ordenado por score).

Pub/Sub

Publicadores enviam mensagens a canais e todos os inscritos recebem na hora; mensagens não ficam guardadas para quem se conectar depois.

Persistência RDB e AOF

RDB salva snapshots periódicos; AOF registra cada escrita. Sem persistência, os dados somem ao reiniciar.

Single-thread

Os comandos são executados um de cada vez, o que os torna atômicos, mas um comando lento bloqueia todos os outros clientes.

Armadilhas & Fixes

ErroCausaCorreção
Redis travou após KEYS *KEYS percorre todas as chaves de uma vez e, como o Redis é single-thread, bloqueia os outros clientes.Use SCAN 0 MATCH 'sessao:*' COUNT 100, que itera em lotes sem bloquear.
OOM command not allowed when used memory > 'maxmemory'A memória chegou ao limite de maxmemory e a política de remoção é noeviction.Para cache, configure maxmemory-policy allkeys-lru; revise TTLs e o tamanho dos valores.
Memória cresce sem pararChaves de cache ou sessão gravadas sem TTL nunca expiram.Grave sempre com expiração (SET chave valor EX 3600) e procure chaves sem TTL com TTL chave (retorna -1).

FLUSHDB apaga tudo

FLUSHDB remove todas as chaves do banco atual (e FLUSHALL, de todos os bancos) sem confirmação. Em produção, considere desabilitar esses comandos com rename-command.
