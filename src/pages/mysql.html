MySQL

banco de dados relacional

Resumo

MySQL é um banco relacional open source muito difundido em aplicações web. Com o engine InnoDB, oferece transações, chaves estrangeiras e replicação nativa.

  • Para que serve: armazenar dados transacionais de aplicações, escalar leitura com réplicas e operar com ferramentas maduras de backup e administração.
  • Quando usar: stacks que já usam MySQL ou MariaDB, aplicações web com muitas leituras simples e ambientes com hospedagem gerenciada (Cloud SQL, RDS).
  • Quando evitar: consultas analíticas pesadas ou recursos avançados como JSONB indexável e tipos customizados, cenários em que o PostgreSQL costuma ser mais adequado.

DDL e transações

No MySQL, comandos de estrutura (DDL) como ALTER TABLE fazem commit implícito: não dá para desfazê-los com ROLLBACK.

Conceitos-chave

InnoDB

Engine de armazenamento padrão: transações ACID, bloqueio por linha, chaves estrangeiras e recuperação após falha.

Índice

Acelera buscas e ordenações. No InnoDB, a chave primária é o índice clusterizado e os índices secundários apontam para ela.

Transação

Agrupa comandos que precisam acontecer juntos com START TRANSACTION, COMMIT e ROLLBACK.

EXPLAIN

Mostra como o MySQL vai executar a query: ordem das tabelas, índice usado e linhas estimadas.

Binlog e replicação

O binary log registra as alterações da primária; as réplicas leem esse log e reaplicam as mudanças.

mysqldump e backup

Gera um backup lógico em SQL. Com --single-transaction, faz uma cópia consistente de tabelas InnoDB sem travar escrita.

📋 DDL - Estrutura

Criar tabelaCREATE TABLE users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) UNIQUE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;
Adicionar colunaALTER TABLE users ADD COLUMN age INT;
Criar índiceCREATE INDEX idx_users_email ON users(email);
Foreign keyALTER TABLE posts ADD CONSTRAINT fk_user
  FOREIGN KEY (user_id) REFERENCES users(id)
  ON DELETE CASCADE;
Criar viewCREATE VIEW active_users AS
SELECT * FROM users WHERE active = 1;
Auto increment customALTER TABLE users AUTO_INCREMENT = 1000;
Enum typeALTER TABLE users ADD COLUMN status ENUM('active', 'inactive', 'banned') DEFAULT 'active';

🔍 Consultas & Joins

JOIN com agregaçãoSELECT u.name, COUNT(p.id) as posts
FROM users u
LEFT JOIN posts p ON u.id = p.user_id
GROUP BY u.id, u.name
HAVING COUNT(p.id) > 0;
SubquerySELECT * FROM users
WHERE id IN (
  SELECT user_id FROM posts
  WHERE created_at > '2023-01-01'
);
Window functionsSELECT name, salary,
  RANK() OVER (ORDER BY salary DESC) as rank
FROM employees;
Full-text searchALTER TABLE articles ADD FULLTEXT(content);
SELECT * FROM articles
WHERE MATCH(content) AGAINST('database query' IN NATURAL LANGUAGE MODE);
JSON operationsSELECT JSON_EXTRACT(data, '$.name') as name,
  JSON_EXTRACT(data, '$.address.city') as city
FROM users WHERE JSON_CONTAINS(data, '{"active": true}');
PaginationSELECT * FROM users
ORDER BY created_at DESC
LIMIT 10 OFFSET 20;

Armadilhas & Fixes

ErroCausaCorreção
ERROR 1045: Access denied for userUsuário, senha ou host não conferem: no MySQL, 'app'@'localhost' e 'app'@'%' são usuários diferentes.Confira com SELECT user, host FROM mysql.user; e crie ou ajuste o usuário para o host certo com CREATE USER e GRANT.
ERROR 1040: Too many connectionsA aplicação abriu mais conexões que max_connections, geralmente por falta de pool ou por conexões que não são fechadas.Use pool de conexões na aplicação, feche as conexões e, se necessário, aumente max_connections.
Emojis viram ???? ou erro 1366A tabela usa utf8 (utf8mb3), que só guarda até 3 bytes por caractere.Use utf8mb4: ALTER TABLE t CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;, e o mesmo charset na conexão.
