Git / GitHub

version control & código

gitgithubmerge15 comandos

Resumo

Git é um controle de versão distribuído: cada clone tem o histórico completo de commits. O GitHub hospeda os repositórios remotos e organiza a revisão de código em pull requests.

  • Para que serve: registrar a evolução do código, trabalhar em paralelo em branches, desfazer erros e integrar mudanças de várias pessoas.
  • Quando usar: em qualquer projeto de código ou texto versionável, inclusive solo; para colaborar com revisão via pull request.
  • Quando evitar: arquivos binários grandes ou que mudam muito (vídeos, datasets) sem Git LFS, e segredos como senhas e chaves, que ficam no histórico mesmo depois de apagados.

Conceitos-chave

Working tree, stage e commit

Você edita na working tree, escolhe o que entra com git add (stage) e grava um snapshot com git commit.

Branch

Ponteiro móvel para um commit. Permite desenvolver uma feature isolada da main e integrá-la depois.

Remote

Cópia do repositório em outro lugar (geralmente origin no GitHub). push envia commits e pull/fetch trazem.

Merge vs Rebase

Merge junta branches criando um commit de merge; rebase reaplica seus commits sobre outra base, deixando o histórico linear.

Pull Request

Pedido no GitHub para integrar uma branch na outra, com diff, revisão, comentários e checagens de CI.

Stash

Gaveta temporária para alterações não commitadas, útil para trocar de branch sem perder o trabalho.

Correções Rápidas

SituaçãoQuando usarComando
Reset suaveDesfazer o último commit mantendo as mudanças no stage, por exemplo para corrigir a mensagem ou incluir um arquivo esquecido.git reset --soft HEAD~1
Reset completoDescartar o último commit e todas as mudanças locais. Só use se o commit ainda não foi enviado.git reset --hard HEAD~1
Remover do stageTirar do stage um arquivo adicionado por engano, sem perder as alterações.git restore --staged arquivo.txt
Descartar alteraçõesVoltar um arquivo ao estado do último commit, perdendo as alterações locais dele.git checkout -- arquivo.txt
Ver histórico compactoEntender o histórico e ver onde cada branch está.git log --oneline --graph --all
Guardar alteraçõesTrocar de branch sem commitar trabalho em andamento.git stash push -m "work-in-progress"

Erros Frequentes

ErroCausaCorreção
CONFLICT (content): Merge conflict in arquivoAs duas branches alteraram as mesmas linhas, e o Git não sabe qual versão manter.Edite os trechos entre <<<<<<< e >>>>>>>, depois git add arquivo e git commit (ou git rebase --continue).
! [rejected] main -> main (non-fast-forward)O remote tem commits que você ainda não tem localmente.Traga as mudanças com git pull --rebase e envie de novo. Evite --force em branches compartilhadas.
You are in 'detached HEAD' stateVocê fez checkout de um commit ou tag em vez de uma branch; novos commits ficam sem branch.Crie uma branch para guardar o trabalho: git switch -c minha-branch, ou volte com git switch main.

Comandos destrutivos

git reset --hard e git checkout -- arquivo descartam alterações não commitadas de forma permanente. Se precisar reescrever o histórico remoto, prefira git push --force-with-lease a --force, e nunca na main compartilhada.
